# 选题雷达安装与部署指南

本文面向第一次使用 Hermes 的用户。完成后，你会在自己的电脑上得到一个独立的 `topic-radar-agent` Profile，并使用自己的模型、搜索服务、资料和飞书机器人。

> 当前版本分发的是 Agent 的身份、工作流和安全规则。模型账户、搜索账户、飞书应用、私有资料和定时任务不会随仓库安装。

## 一、安装前检查

需要准备：

1. Hermes Agent `>= 0.20.1`；
2. Git；
3. 可用的模型提供商；
4. 如需公开网页研究，一个可用的 Web Search 配置；
5. 只在需要消息入口时准备飞书账号与应用权限。

检查版本：

```bash
hermes --version
git --version
```

如果尚未安装 Hermes，请按 [官方安装指南](https://hermes-agent.nousresearch.com/docs/getting-started/installation) 操作。Windows 用户可使用官方 Desktop 安装器，或在 PowerShell 中运行官方安装命令；Linux、macOS 和 WSL2 使用官方页面给出的对应命令。

## 二、安装 Agent

在终端或 PowerShell 中运行：

```bash
hermes profile install github.com/YFpsy/topic-radar-github --alias
```

安装器会：

1. 下载仓库；
2. 读取并展示 `distribution.yaml`；
3. 检查 Hermes 版本和声明的环境变量；
4. 在确认后创建独立 Profile；
5. 安装根目录 `SOUL.md`；
6. 创建 `topic-radar-agent` 命令别名。

如果希望先审阅再安装，可先下载本仓库，然后从本地目录安装：

```bash
git clone https://github.com/YFpsy/topic-radar-github.git
cd topic-radar-agent
hermes profile install . --alias
```

不要使用来源不明的分支或修改版 Profile。`SOUL.md` 会在启动该 Agent 时生效，安装前阅读它是合理的安全步骤。

## 三、确认安装成功

```bash
hermes profile info topic-radar-agent
hermes profile list
hermes profile show topic-radar-agent
```

检查结果中应能看到：

- Profile 名称为 `topic-radar-agent`；
- 来源指向本仓库；
- Hermes 版本要求已满足；
- Distribution 信息存在；
- 使用 `--alias` 安装后，可以识别 `topic-radar-agent` 命令。

若别名尚未生效，先关闭并重新打开终端；也可以始终使用完整形式：

```bash
hermes -p topic-radar-agent chat
```

## 四、建立私有运行配置

安装目录中的 `TOPIC_RADAR_CONFIG.example.md` 是空白模板。复制它，不要直接在模板中保存自己的资料。

目标文件为：

```text
$HERMES_HOME/local/topic-radar.local.md
```

使用 `hermes -p topic-radar-agent ...` 或 `topic-radar-agent ...` 时，Hermes 会把 `$HERMES_HOME` 指向这个独立 Profile。不要在没有核实的情况下猜绝对路径。

默认安装中，底层 Profile 目录通常位于：

- macOS / Linux / WSL2：`~/.hermes/profiles/topic-radar-agent/`
- Windows 原生版：`%LOCALAPPDATA%\hermes\profiles\topic-radar-agent\`

如果你设置过自定义 Hermes 数据目录，以 `hermes profile show topic-radar-agent` 显示的实际路径为准。

### macOS / Linux / WSL2 示例

```bash
PROFILE_HOME="${HERMES_HOME:-$HOME/.hermes}/profiles/topic-radar-agent"
mkdir -p "$PROFILE_HOME/local"
cp "$PROFILE_HOME/TOPIC_RADAR_CONFIG.example.md" \
  "$PROFILE_HOME/local/topic-radar.local.md"
```

### Windows PowerShell 示例

```powershell
$ProfileHome = Join-Path $env:LOCALAPPDATA 'hermes\profiles\topic-radar-agent'
New-Item -ItemType Directory -Force -Path (Join-Path $ProfileHome 'local')
Copy-Item -LiteralPath (Join-Path $ProfileHome 'TOPIC_RADAR_CONFIG.example.md') `
  -Destination (Join-Path $ProfileHome 'local\topic-radar.local.md')
```

编辑新文件，至少填写：

- 账号定位和目标受众；
- 允许读取的定位、历史选题和素材范围；
- 不允许发送到外部服务的内容；
- 输出位置和输出偏好；
- 时区、时间范围和去重范围。

本地配置中应填写**资料路径或规则**，不要填写 API Key。API Key 应放在 Hermes 支持的凭据界面、环境变量、Profile 私有 `.env` 或系统密钥管理工具中。

## 五、配置模型与搜索

先完成基础配置：

```bash
topic-radar-agent setup
```

也可以分别配置：

```bash
topic-radar-agent model
topic-radar-agent tools
```

建议顺序：

1. 选择并验证模型提供商；
2. 先完成一次普通对话，确认模型可以响应；
3. 在工具设置中启用 Web Search；
4. 选择 Hermes 当前支持的搜索服务，并使用自己的账户或凭据；
5. 再测试一次带公开来源的检索任务。

Tavily 是本项目验证过的一种搜索方案，但不是强制依赖。只要当前 Hermes 版本支持、并且能够返回可追溯的公开来源，就可以换成其他搜索后端。不同服务的额度和计费由使用者自行承担。

使用云端模型时，模型提供商可能会接收本次任务所需的运行上下文。部署者应先确认提供商的数据政策，只授权任务必需的资料，并避免把原始笔记、评论、个人信息和密钥放进外部请求。

## 六、首次自检

启动独立 Profile：

```bash
topic-radar-agent chat
```

先发送：

```text
请先进行运行前自检，不要开始正式选题。检查：
1. 是否加载了选题雷达 Profile；
2. 是否能读取我的本地配置；
3. 哪些资料范围已授权；
4. 模型与 Web Search 是否可用；
5. 输出目录是否可写。
只报告检查结果，发现缺失就停止并告诉我如何补齐。
```

只有在五项检查符合预期后，再发送正式任务：

```text
请为今天完成一次正式选题。先读取我的账号定位与历史选题，再检索并核验公开来源，与历史主题去重，输出最多 3 个候选选题和 1 个推荐选题。每个选题都要说明目标读者、解决的问题、内容角度、来源依据和风险。不要发布，等我最终确认。
```

第一次建议只授权少量非敏感样例资料。确认读取范围、外发内容和输出位置都正确后，再逐步扩大范围。

## 七、可选：接入飞书

应先确认终端内的 `topic-radar-agent chat` 能正常工作，再配置消息平台。

```bash
hermes -p topic-radar-agent gateway setup
```

在向导中选择 Feishu / Lark，并按提示完成扫码创建或手动填写自己的 App ID 与 App Secret。推荐使用 WebSocket 模式；它不需要公开 webhook 地址。

然后启动该 Profile 的 gateway：

```bash
hermes -p topic-radar-agent gateway
```

测试顺序：

1. 私聊机器人，要求只回复当前 Profile 名称；
2. 发送“运行前自检”，确认没有意外读取其他 Profile；
3. 在测试群中 `@机器人` 发一条小任务；
4. 确认使用者白名单、群聊策略和输出范围；
5. 最后再发送正式选题任务。

不要把 App Secret 截图、写入 Markdown 或提交到 GitHub。生产使用时应配置飞书使用者白名单，并确保同一个 App ID 没有被另一套 Hermes gateway 同时占用。

`SOUL.md` 中的“只接受授权用户”“限制读取范围”等文字属于行为约束，不能代替真正的访问控制。飞书允许谁触发、机器人能读写哪些文件、单次运行可花多少搜索或模型额度，以及最大运行时长和失败重试次数，都必须在 Hermes Gateway、操作系统权限或相应服务后台设置。

飞书的最新权限、连接模式和排错说明见 [Hermes 官方 Feishu / Lark 指南](https://hermes-agent.nousresearch.com/docs/user-guide/messaging/feishu)。

## 八、更新

```bash
hermes profile update topic-radar-agent
```

Hermes 会重新读取仓库并更新 Distribution 管理的文件。`local/`、`.env`、记忆、会话和运行状态属于使用者数据，正常更新不会覆盖。

更新后建议执行：

```bash
hermes profile info topic-radar-agent
```

然后新开一个会话做“运行前自检”。如果你修改过 Distribution 管理的 `SOUL.md`，更新可能覆盖该修改；个人差异应写在 `local/topic-radar.local.md`，不要直接改公共 `SOUL.md`。

## 九、卸载

```bash
hermes profile delete topic-radar-agent
```

删除 Profile 会同时删除它的本地配置、密钥、记忆、会话和运行数据。执行前先备份你确实需要保留的本地文件，并仔细阅读 Hermes 的删除确认信息。

## 十、常见问题

### 1. 提示 Hermes 版本过低

先升级 Hermes，确保版本满足 `distribution.yaml` 的 `hermes_requires`，然后重新安装。不要绕过版本检查。

### 2. 找不到 `topic-radar-agent` 命令

重新打开终端。仍不可用时使用：

```bash
hermes -p topic-radar-agent chat
```

并用 `hermes profile info topic-radar-agent` 确认 Profile 已安装。

### 3. Profile 已存在

不要在不清楚后果时使用强制覆盖。先查看：

```bash
hermes profile info topic-radar-agent
```

如需保留旧 Profile，可用其他名称安装：

```bash
hermes profile install github.com/YFpsy/topic-radar-agent --name topic-radar-agent-test --alias
```

### 4. Agent 能聊天，但不会检索网页

运行 `topic-radar-agent tools`，确认 Web Search 已启用且凭据有效。先用一个普通公开问题单独验证检索，再运行完整选题流程。

### 5. Agent 的输出太泛或不符合账号定位

检查 `local/topic-radar.local.md` 是否存在、是否填写了定位、受众、历史选题范围与内容边界；再确认资料路径对当前 Hermes 进程可读。

### 6. 飞书私聊或群聊没有回复

检查 gateway 是否正在运行、飞书 App ID 和 App Secret 是否正确、发信人是否在白名单内。群聊中需要 `@机器人`。同一个飞书 App ID 同一时间只应连接一套 Hermes 实例。

### 7. 担心资料被发送到外部服务

先停止正式运行，缩小授权目录，只使用脱敏样例做测试。公开搜索只需要发送非敏感检索词；原始笔记、草稿、评论、个人信息和密钥不应发送给搜索服务。

### 8. 如何限制成本或避免任务长时间运行

在搜索服务和模型提供商后台设置用量或账单上限，并在 Hermes Gateway 或运行环境中限制单次任务的搜索次数、最大运行时长和失败重试次数。私有配置里的预算文字用于指导 Agent，但不是技术层面的硬限制。

## 十一、手动参考路径

如果你的环境暂时不能使用 Distribution 安装，可以把本仓库作为实施参考，但不要把 `docs/04-Hermes-Profile.template.md` 当成已经生效的 Profile：

1. 按当前 Hermes 版本创建一个名为 `topic-radar-agent` 的独立 Profile；
2. 以根目录 `SOUL.md` 作为运行规则来源；
3. 在该 Profile 的 `local/` 下建立 `topic-radar.local.md`；
4. 使用自己的模型、搜索服务和消息平台凭据；
5. 通过 `hermes profile info`、启动日志和实际自检确认 Hermes 读取的是哪个文件；
6. 按 `docs/07-测试与验收.md` 完成端到端测试。

手动复制无法获得 Distribution 的更新记录和所有权边界，优先推荐升级 Hermes 后使用正式安装命令。
