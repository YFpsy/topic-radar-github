# 选题雷达｜安装与部署指南

本文帮助你把“选题雷达”安装为一个独立的 Hermes Agent，并接入自己的模型、搜索服务、资料和飞书机器人。

## 先分清两个名称

| 用途 | 名称 |
| --- | --- |
| GitHub 仓库名称 | `topic-radar-github` |
| Hermes Profile / Agent 名称 | `topic-radar-agent` |

因此：

- GitHub 下载或安装地址中使用 `topic-radar-github`；
- Hermes 启动、查看和更新 Profile 时使用 `topic-radar-agent`。

这两个名称不同是正常的，不需要把文档中所有 `topic-radar-agent` 都替换掉。

## 一、安装前准备

需要：

1. Hermes Agent `>= 0.20.1`；
2. Git；
3. 由你自己配置的模型服务；
4. 如需联网研究，配置一种 Hermes 支持的 Web Search 服务；
5. 如需通过飞书使用，再准备自己的飞书应用。

检查版本：

```bash
hermes --version
git --version
```

尚未安装 Hermes 时，请使用 [Hermes 官方安装指南](https://hermes-agent.nousresearch.com/docs/getting-started/installation)。

## 二、安装选题雷达

在终端或 PowerShell 中运行：

```bash
hermes profile install github.com/YFpsy/topic-radar-github --alias
```

安装器会读取仓库根目录的 `distribution.yaml`，并把 `SOUL.md` 安装到独立 Profile 中。安装时请阅读清单并确认来源。

如果希望先下载并审阅：

```bash
git clone https://github.com/YFpsy/topic-radar-github.git
cd topic-radar-github
hermes profile install . --alias
```

## 三、确认 Hermes 已识别

```bash
hermes profile list
hermes profile info topic-radar-agent
hermes profile show topic-radar-agent
```

应当看到：

- Profile 名称为 `topic-radar-agent`；
- Distribution 来源为本 GitHub 仓库；
- `SOUL.md` 存在；
- Hermes 版本符合要求；
- 使用 `--alias` 安装后，可以调用 `topic-radar-agent` 命令。

如果别名暂时不可用，重新打开终端，或者使用：

```bash
hermes -p topic-radar-agent chat
```

## 四、创建私有运行配置

公开仓库只提供空白模板：

```text
TOPIC_RADAR_CONFIG.example.md
```

不要直接把私人资料写进公开模板。请把它复制到当前 Profile 的：

```text
$HERMES_HOME/local/topic-radar.local.md
```

运行 `topic-radar-agent` 时，`$HERMES_HOME` 表示这个独立 Profile 的目录。

常见默认位置：

- Windows：`%LOCALAPPDATA%\hermes\profiles\topic-radar-agent\`
- macOS / Linux / WSL2：`~/.hermes/profiles/topic-radar-agent/`

实际路径以这条命令显示的结果为准：

```bash
hermes profile show topic-radar-agent
```

### Windows PowerShell

```powershell
$ProfileHome = Join-Path $env:LOCALAPPDATA 'hermes\profiles\topic-radar-agent'
New-Item -ItemType Directory -Force -Path (Join-Path $ProfileHome 'local')
Copy-Item -LiteralPath (Join-Path $ProfileHome 'TOPIC_RADAR_CONFIG.example.md') `
  -Destination (Join-Path $ProfileHome 'local\topic-radar.local.md')
```

### macOS / Linux / WSL2

```bash
PROFILE_HOME="$HOME/.hermes/profiles/topic-radar-agent"
mkdir -p "$PROFILE_HOME/local"
cp "$PROFILE_HOME/TOPIC_RADAR_CONFIG.example.md" \
  "$PROFILE_HOME/local/topic-radar.local.md"
```

编辑新的私有配置，至少填写：

- 账号定位和目标读者；
- 允许读取的资料范围；
- 历史选题、素材和草稿的位置；
- 输出位置；
- 不得发送给外部服务的内容；
- 时区、去重范围和预算边界。

API Key 不要写进 Markdown。请使用 Hermes 支持的凭据配置、Profile 私有 `.env` 或系统密钥管理工具。

## 五、配置模型与搜索

```bash
topic-radar-agent setup
```

也可以分别配置：

```bash
topic-radar-agent model
topic-radar-agent tools
```

建议顺序：

1. 选择并验证自己的模型；
2. 先进行一次普通对话；
3. 启用 Web Search；
4. 使用自己的搜索账户或凭据；
5. 再测试带公开来源的检索。

Tavily 是本项目验证过的搜索方案，但不是强制依赖。只要 Hermes 当前支持，并且能返回可追溯的公开来源，也可以使用其他搜索后端。

## 六、第一次自检

启动：

```bash
topic-radar-agent chat
```

先发送：

```text
请先进行运行前自检，不要开始正式选题。检查：
1. 是否加载了选题雷达 Profile；
2. 是否能读取我的私有配置；
3. 哪些资料范围已经授权；
4. 模型与 Web Search 是否可用；
5. 输出目录是否可写。
只报告检查结果，发现缺失就停止并告诉我如何补齐。
```

自检通过后，再发送正式任务：

```text
请为今天完成一次正式选题。先读取我的账号定位与历史选题，再检索并核验公开来源，与历史主题去重，输出最多 3 个候选选题和 1 个推荐选题。每个选题都要说明目标读者、解决的问题、内容角度、来源依据和风险。不要发布，等我最终确认。
```

第一次只授权少量非敏感样例资料。确认读取范围、外发内容和输出位置正确后，再逐步扩大范围。

## 七、可选：接入飞书

先确认终端中的 `topic-radar-agent chat` 可以正常工作，再配置飞书：

```bash
hermes -p topic-radar-agent gateway setup
```

按向导选择 Feishu / Lark，并填写自己的 App ID 与 App Secret。凭据不得写入公开仓库。

启动 Gateway：

```bash
hermes -p topic-radar-agent gateway
```

建议按以下顺序测试：

1. 私聊机器人，只询问当前 Profile 名称；
2. 发送“运行前自检”；
3. 在测试群中 `@机器人` 发一个小任务；
4. 检查使用者白名单、群聊策略和输出范围；
5. 最后再运行正式选题。

`SOUL.md` 中的安全规则只是行为约束，不能代替真正的访问控制。飞书使用者白名单、文件权限、费用上限、最大运行时长和重试次数，必须在 Hermes Gateway、操作系统或对应服务后台设置。

## 八、更新

```bash
hermes profile update topic-radar-agent
```

更新后运行：

```bash
hermes profile info topic-radar-agent
```

然后新开会话重新进行运行前自检。`local/` 中的个人配置通常会保留；不要把个人差异直接写进公共 `SOUL.md`。

## 九、卸载

```bash
hermes profile delete topic-radar-agent
```

删除 Profile 可能同时删除其中的私有配置、密钥、记忆、会话和运行数据。执行前先备份需要保留的内容，并阅读 Hermes 的删除确认信息。

## 十、隐私与安全

- 不要把 API Key、App Secret、访问令牌或验证码提交到 GitHub；
- 不要上传真实 `config.yaml`、`.env`、授权名单、聊天记录、运行数据库或私人笔记；
- 只向搜索服务发送必要的非敏感搜索词；
- 使用云端模型时，完成任务所需的上下文可能会发送给模型服务商；
- 先确认服务商的数据政策，只授权最小必要资料；
- `.gitignore` 能降低误上传风险，但不能删除已经进入 Git 历史的秘密；
- 成本和权限限制必须在系统层真正配置，不能只写在提示词里。

## 十一、常见问题

### 找不到 `topic-radar-agent` 命令

重新打开终端，或者使用：

```bash
hermes -p topic-radar-agent chat
```

### Agent 能聊天但不能搜索

运行：

```bash
topic-radar-agent tools
```

检查 Web Search 是否启用、搜索凭据是否有效，并先用普通公开问题单独测试搜索。

### 输出太泛或不符合定位

检查 `local/topic-radar.local.md` 是否已经填写账号定位、目标读者、历史选题范围与内容边界。

### 飞书没有回复

检查 Gateway 是否运行、App ID 与 App Secret 是否正确、发信人是否在白名单内。群聊中需要明确 `@机器人`。

### 担心任务费用过高

在模型和搜索服务后台设置用量或账单上限，并限制单次任务的搜索次数、最长运行时间和失败重试次数。
